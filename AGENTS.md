# Project instructions

- Project rules are authoritative and directly readable without an installed Skill. Start with `standards/foundation/project.md`.
- For changes to scripts, tests or package configuration, read `standards/engineering/node.md`. For implementation, verification or review, read `standards/quality/testing.md`. For Git delivery, read `standards/delivery/git.md`. For high-risk work, read `standards/governance/collaboration.md`.
- Read applicable rules in full and follow their conditions. Use the project-owned commands in `package.json`; record actual verification and preserve unrelated worktree changes.
- ZipZap is optional assistance for rule discovery, related documents, checks and handoffs. Ordinary work does not require a Loop. Use governed delivery when requested or required by project policy; never bypass a required check or claim missing evidence.
- When developing or testing ZipZap itself, this repository's `SKILL.md` and `scripts/zipzap.mjs` are the source entrypoints. This does not require installing the Skill.
- If optional assistance is unavailable, continue ordinary work from project rules. If a required check is unavailable, block the affected delivery boundary and state what is missing.
- Review changes to project rules and this entry before applying them; do not automatically append rules or relocate documents.
